Boosted trees: from training to testing

  1. Train on ten seasons · 2014–15 through 2023–24

    The boosted trees use pregame stats and actual final scores from 12,795 games to learn the point margin. A prediction of +7 means the home team is projected to win by seven points.

  2. Calibrate on the next season · 2024–25

    The trees stay fixed. A separate logistic regression uses predicted margins and actual winners from 1,315 games to learn what win probability to assign to a margin like +7.

  3. Test on a later season · 2025–26

    Both models stay fixed. The system uses pregame data to pick the team with the higher win probability. It picked 907 of 1,316 winners correctly (68.92%).

How the transformer works

The transformer was tested separately. The 68.92% result above came from the boosted trees. View transformer code.

Show the seven transformer steps
StepWhat it doesWhy it helps
1. Build the game tokensGive each team, coach and starter its own token. Add a WINNER token to collect information for the pick.The model can compare individual starters and lineups.
2. Turn each token into numbersAdd three learned 128-value vectors: one for identity, one for home or away, and one made from the token’s pregame stats.Every token has the same shape, while retaining who it represents and how they’ve played.
3. Let tokens compare with attentionLearn three matrices called query, key and value. Query and key decide how strongly tokens relate; value supplies the information to pass along. In the bidirectional winner model, every game token can see the others.A starter can use information about both teammates and opponents.
4. Refine those comparisonsEach of the two transformer layers uses attention and a feedforward network, which mixes the values inside each token.The second layer can build on comparisons the first layer already made.
5. Read the WINNER tokenUse its final vector to produce a home-win score. The optional margin head also predicts home points minus away points.The win output learns who won; the margin output gives training a way to tell close calls from blowouts.
6. Update the weightsCompare the outputs to the actual result, backpropagate the error, and let AdamW update the learned weights after each batch. In the margin-enabled setting described here, margin error is weighted by 0.25.The embeddings and attention matrices learn from games without hand-tuned weights.
7. Pick a winnerFor a new game, use the learned weights and pregame inputs. Convert the home-win score to a probability with sigmoid. Pick home at 50% or higher.Each game gets both a pick and a probability.

Measured inputs and derived variables

Explore the original data and the engineered inputs. The trees use 432 matchup columns built from team stats and summaries of the starters.

Measured inputs and raw data sources
  • Game records: NBA game ID, date, season, phase, playoff round and series, home and away team IDs, neutral-site flag, and final scores.
  • Team game logs: Pace, offensive rating, defensive rating, effective field-goal percentage, turnover rate, offensive rebounding rate, free-throw and field-goal attempts, and player-minutes summed by team.
  • Player game logs: Player and team IDs, points, rebounds, assists, minutes, field-goal attempts, and free-throw attempts. Bench box scores contribute to earlier rotation and career history.
  • Start and rotation records: Starter IDs and on/off court times by player. Older starting fives come from opening stints where those stints agree with the box score.
  • Play-by-play shots: Shot value, distance and court coordinates, used to build prior shot profiles.

The importer joins the NBA data archive by game, team and player IDs. It writes games-expanded.jsonl. The feature builder processes that file in date order. The final score supplies the training target and can update stats for later dates. A game's own box score and play-by-play stay out of its inputs.

How the trees use the variables

For each side, keep the 75 team values and calculate the mean, maximum, and minimum across the starters for each of the 23 player values. That gives 144 numbers per side. Place the home values, away values, and home-minus-away differences side by side for 432 columns. For example, the model can split on the away team's rest, the highest starter scoring average, or the difference between the teams’ typical scoring margins.

Below, each row describes the value before the home/away comparison or starter summary. Missing history generally contributes zero, with sample counts or known flags where available. The optional playoff start date has no values in this dataset. Recorded starters are treated as known before tipoff.

Inside the boosted trees

Show the full workflow and learned criteria
  1. Build the pregame snapshot. Walk through games by date and calculate each day's inputs before adding its results to history. The replay assumes recorded starters were known at tipoff.
  2. Turn two lineups into one row. Each side contributes 75 team inputs and 69 starter summaries. The summaries are the mean, maximum, and minimum of each of 23 player inputs. Add 144 home-minus-away differences for 432 inputs.
  3. Learn point margin. Train on 12,795 games. The target is final home points minus final away points. Each of 180 trees uses earlier errors to learn where to adjust the predicted margin. The learning rate is 0.05, and each tree has up to 15 leaves.
  4. Convert margin to a win chance. Logistic calibration uses 1,315 games from 2024–25. It learns a probability curve from predicted margins and observed winners. Pick home at 50% or higher.
  5. Replay the test season. The fitted trees and calibration stay fixed. Completed games refresh the inputs for later dates.
